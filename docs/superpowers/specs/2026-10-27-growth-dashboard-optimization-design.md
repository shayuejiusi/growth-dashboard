# 个人工作与能力提升看板全站优化设计

日期：2026-10-27
状态：设计已确认，等待书面说明复核

## 1. 背景与目标

现有项目采用 Java 17、Spring Boot 3、原生 HTML/CSS/JavaScript 和 ECharts，前端随后端 JAR 一起部署。本次将全站迁移为前后端完全分离架构，在保留现有业务与数据的基础上，统一视觉、交互、响应式和异常状态，并新增任务拖拽排序、全局搜索和深色模式。

目标：

- 提升全站视觉一致性、操作效率和长期可维护性。
- 前端与后端可独立开发、构建、发布和回滚。
- 保留现有后端能力，避免不必要的数据迁移和业务重写。
- 覆盖桌面、平板和手机，以及加载、错误、空状态和操作反馈。
- 控制依赖，仅引入有明确职责的库。

## 2. 已确认的范围

### 2.1 保留并迁移的功能

- 登录、退出和角色权限。
- 今日驾驶舱、今日重点和统计信息。
- 工作任务管理、快速新增、筛选、完成、编辑、备份等现有操作。
- 待办提醒中心。
- 每日精选。
- 账号管理。
- 日复盘与人才筛选、花名册和人才九宫格。
- AI 状态及现有 AI 相关能力。

### 2.2 新增功能

- 任务拖拽排序：支持鼠标、触屏和键盘操作，顺序持久化。
- 全局搜索：通过顶部入口或 Ctrl/Cmd + K 唤起，分类搜索任务、人员和内容。
- 深色模式：支持明暗主题切换并记住用户偏好。

### 2.3 暂时隐藏的功能

- 前端移除能力成长地图和能力评估页面、导航与路由。
- 隐藏驾驶舱中的能力评估摘要。
- 移除 AI 重新评估等能力评估入口。
- 能力评估内容不进入全局搜索结果。
- 后端相关接口、数据结构和已有数据全部保留，后续可重新接入前端。

### 2.4 非目标

- 本次不增加任务数据导出。
- 不重写已有业务规则，不更换数据库。
- 不引入微前端、微服务或额外客户端。
- 不将密钥或长期访问令牌存入浏览器 localStorage。

## 3. 架构设计

### 3.1 总体结构

采用前后端完全分离部署：

```text
浏览器
  ├─ dashboard.example.com：React SPA，由 Nginx / 静态托管 / CDN 提供
  └─ api.example.com：Spring Boot REST API，连接数据库与 AI 服务
```

以 `growth-dashboard` 作为唯一交付根目录，内部划分独立 `frontend` 与现有后端，二者通过类型明确的 HTTP API 交互。前端、后端、测试、组件源码、部署配置、启动脚本和文档全部收纳在该目录，最终代码不引用其他工作区文件。生产环境使用 HTTPS；开发环境通过 Vite 代理访问后端，避免开发期跨域差异。

### 3.2 前端技术栈

- React、TypeScript、Vite：应用与构建基础。
- Tailwind CSS、shadcn/ui、Radix UI：设计系统与无障碍基础组件。
- TanStack Query：服务端请求、缓存、失效、重试和加载状态。
- Zustand：主题、侧栏、搜索面板等客户端 UI 状态，不复制服务端数据。
- dnd-kit：任务拖拽排序与键盘操作。
- Recharts：保留业务所需的数据可视化能力。
- Lucide React：统一图标。
- Motion：少量有明确反馈目的的过渡动画。

不重复引入功能相近的状态、请求、图表或动画库。

### 3.3 前端模块边界

- `app`：启动、路由、应用外壳、权限边界和全局 Provider。
- `components/ui`：可控的 shadcn/ui 基础组件。
- `components/feedback`：Alert、Toast、确认和状态组件。
- `features/auth`：登录、会话和角色。
- `features/dashboard`：今日驾驶舱，不含能力评估摘要。
- `features/tasks`：任务列表、筛选、表单、快速新增和排序。
- `features/reminders`：待办提醒。
- `features/content`：每日精选。
- `features/admin`：账号管理。
- `features/review`：日复盘。
- `features/talent`：人才九宫格与花名册。
- `features/search`：全局搜索面板和分类结果。
- `lib/api`：API Client、错误模型和请求配置。

每个业务模块拥有自己的页面、组件、请求和类型，跨模块共享只通过明确接口完成。

### 3.4 后端调整

保留现有 Spring Boot 控制器、服务、实体和数据，不再承担新前端静态资源托管。新增或调整：

- 全局搜索接口：统一返回任务、人员和内容分类结果，并按当前用户权限过滤。
- 任务排序接口：批量提交有序任务 ID，服务端校验归属、完整性和并发版本后持久化。
- 统一错误结构：错误码、可读消息和请求标识。
- CORS、凭证和 CSRF 配置：仅允许明确配置的前端来源。
- 独立 API 健康检查与配置项。

现有能力评估相关 API 保持可用。

### 3.5 鉴权与权限

采用 HttpOnly Cookie 会话，生产环境采用同站子域名并启用 HTTPS、凭证跨域和 CSRF 防护。后端是所有数据与操作权限的最终裁决者，前端角色控制只负责可见性和导航。

登录失效时统一返回登录页，并记录原路由；重新登录后恢复。权限不足显示明确反馈，不通过隐藏按钮替代后端校验。

### 3.6 数据流

```text
用户操作
  → React 页面 / 业务组件
  → TanStack Query 或 API Client
  → HTTPS + HttpOnly Cookie + CSRF 防护
  → Spring Boot 鉴权与参数校验
  → 业务服务 / 数据库 / AI 服务
  → 统一响应
  → Query 缓存更新
  → 页面反馈
```

Zustand 仅管理本地 UI 状态。任务等服务端数据以 TanStack Query 缓存为准，避免双数据源。

## 4. 界面与交互设计

### 4.1 视觉语言

采用已确认的专业侧边导航与暖白、墨绿风格：

- 暖白页面背景、白色内容卡片、墨绿主操作色。
- 中性色承担文字和边框，红色仅用于逾期、危险和破坏性操作。
- 8px 间距体系，12px 卡片圆角，轻量边框和克制阴影。
- Lucide 图标替换表情符号。
- 动画时长通常为 150–250ms，支持减少动态效果偏好。
- 深色模式使用深灰绿而非纯黑，保持文本、边框和状态色的对比度。

### 4.2 导航与响应式

- 桌面端：固定侧边导航；顶部包含全局搜索、主题切换、用户菜单和新建任务。
- 平板端：侧栏可折叠为图标栏，并保留可访问名称。
- 手机端：导航使用 Drawer，内容单列，主要操作易触达。
- 业务页面使用独立路由，不以多层弹窗替代页面切换。
- 能力成长与能力评估不出现在导航、路由、驾驶舱或搜索中。

### 4.3 任务交互

- 保留现有任务分类、筛选、优先级、来源、截止时间和完成操作。
- 支持完整表单编辑、快速新增和 AI 识别流程。
- 拖拽排序先乐观更新，再调用后端；失败回滚并提示。
- 排序保存中防止同一列表并发提交，避免后到的旧响应覆盖新顺序。
- 删除等可撤销操作直接执行并提供撤销；高风险清空操作使用强制确认。
- 表单即时校验，提交中禁用重复提交，失败保留输入。

### 4.4 全局搜索

- 顶部搜索入口与 Ctrl/Cmd + K 共用搜索面板。
- 输入去除首尾空白后至少 1 个字符即发起搜索，防抖时间为 300ms，关键词最长 50 个字符。
- 结果按任务、人员、内容分类，支持键盘导航和空结果状态。
- 选择结果后进入对应页面或编辑上下文。
- 不返回当前用户无权访问的内容，不返回能力评估内容。

### 4.5 六类弹出组件规范

按打扰程度从轻到重使用：

1. Tooltip：悬停或聚焦显示简短辅助说明，不放关键信息。
2. Toast：短时自动消失，用于操作结果反馈；撤销入口可用于可恢复操作。
3. Alert：顶部常驻条，用于服务异常、AI 不可用等系统重要提醒，恢复后移除。
4. Popconfirm：按钮旁小气泡，用于高频、轻量且确需确认的操作。
5. Modal：居中蒙层，用于短内容或必须强制处理的高危操作。
6. Drawer：侧边滑出，用于长表单、名册管理及需要对照页面上下文的编辑。

附加规则：

- 内容短用 Modal，长内容或需对照用 Drawer，业务流程切换用新页面。
- 表单弹层不通过点击蒙层关闭。
- 有未保存内容时，关闭前明确提示。
- 可撤销操作不二次确认。
- 按钮写清具体动作，例如“清空全部任务”，避免笼统的“确定”。
- 不叠加多个 Modal 或 Drawer 完成单一任务。

### 4.6 加载、错误与空状态

- 首次加载使用与页面结构匹配的骨架屏。
- 局部刷新保留现有数据，避免整页闪烁。
- 空状态说明原因，并提供可执行的下一步。
- 字段错误靠近字段展示，提交错误靠近表单操作区展示。
- 网络失败允许重试；系统级持续异常使用 Alert。
- 成功反馈使用轻量 Toast，不打断连续操作。

## 5. 可靠性与安全

- API Client 统一处理网络错误、401、403、服务异常和请求标识。
- 所有后端写操作进行鉴权、参数校验和必要的 CSRF 防护。
- CORS 不使用允许任意来源携带凭证的配置。
- 前端环境变量仅包含 API 地址等公开配置，密钥仅存服务端。
- 排序请求校验任务归属、ID 集合和版本，避免覆盖其他列表或其他用户的数据。
- 搜索接口限制关键词长度、结果数量和权限范围。
- AI 不可用时保留非 AI 核心功能，并给出明确状态。

## 6. 部署设计

### 6.1 开发环境

- 前端由 Vite Dev Server 启动，支持命令行 host 和 port 参数。
- `/api` 通过开发代理访问独立 Spring Boot 服务。
- 前后端分别提供启动、构建、检查和测试命令。

### 6.2 生产环境

- 前端构建为静态文件，由 Nginx、静态托管或 CDN 发布。
- 后端构建为独立 JAR，由现有服务管理方式运行。
- 前后端版本可独立发布，API 变更保持向后兼容。
- 部署配置包含前端 API 地址、允许来源、HTTPS、Cookie、CSRF 和健康检查。
- 提供独立回滚方式和启动说明，不在仓库写入真实密钥。

## 7. 测试策略

### 7.1 前端

- 单元测试：格式化、权限展示、搜索和状态工具函数。
- 组件测试：表单校验、任务操作、六类弹层、加载/错误/空状态。
- 交互测试：拖拽、键盘排序、搜索面板、主题切换。
- 响应式与基础无障碍检查：桌面、平板、手机、键盘导航、焦点管理和对比度。

### 7.2 后端

- 集成测试：登录、角色权限、全局搜索和任务排序。
- 回归测试：现有任务、提醒、内容、账号、复盘与人才接口。
- 能力评估接口保留验证：前端隐藏不影响后端可访问性。

### 7.3 端到端

覆盖登录、任务新增/编辑/完成、拖拽排序、全局搜索、主题切换、权限隔离和异常恢复。验证开发代理与生产跨域两种运行方式。

## 8. 验收标准

- 前端与后端生产构建通过，自动化测试通过。
- 两个应用可独立启动、构建和部署。
- 除明确隐藏的能力模块外，现有功能均完成迁移并保持可用。
- 任务拖拽排序可持久化，支持失败回滚和键盘操作。
- 全局搜索分类正确、权限正确，支持快捷键与空结果。
- 深色模式和用户主题偏好正常工作。
- 全部页面具备必要的加载、错误、空状态和操作反馈。
- 六类弹层按已确认规则使用，表单不会被蒙层点击意外关闭。
- 能力评估入口完全隐藏，对应后端接口保留。
- 桌面、平板和手机无阻断性布局问题。
- 提供前后端分离部署配置与启动说明。

## 9. 实施顺序

1. 建立前后端分离骨架、环境配置和 API 约定。
2. 建立设计系统、应用外壳、鉴权与权限边界。
3. 迁移驾驶舱、任务和提醒，完成拖拽排序。
4. 迁移每日精选、账号、复盘和人才功能。
5. 完成全局搜索、深色模式和全站状态反馈。
6. 完成响应式、无障碍、测试、构建和独立部署验证。
