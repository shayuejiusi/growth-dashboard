# 个人工作看板 · 独立部署手册

适用环境：Linux、Java 17、Maven 3.9、Node 22.22+、Nginx 1.25+。前端与后端可分机、分进程发布；以下示例域名和路径均为占位符，部署时统一替换，不要写入真实密码或密钥。

## 1. 架构与端口

```text
浏览器 ─HTTPS→ dashboard.example.com（前端 Nginx）
                   ├─ /、/assets/** → frontend/dist
                   └─ /api/** ─HTTPS→ api.example.com（API Nginx）─HTTP→ 127.0.0.1:7100
```

- 前端构建产物为 `frontend/dist`，后端构建产物为 `target/growth-dashboard-1.0.0.jar`。
- Spring Boot 只暴露 `/api/**`，不提供 SPA fallback；`src/main/resources/static` 旧文件暂存但未映射。
- 7100 不对公网开放。API 服务器防火墙仅允许 80/443，7100 仅允许本机访问。
- 生产前端默认使用同源 `/api`；`VITE_API_PROXY_TARGET` 仅用于开发，不是生产环境变量。

## 2. 本地构建

在项目根目录执行：

```bash
mvn clean test
mvn package
cd frontend
npm ci
npm run lint
npm test
npm run build
```

只上传 `frontend/dist` 到前端服务器，只上传 Jar、systemd unit 和 API 配置到 API 服务器。不要将 `.env*`、数据库文件、日志或测试记录发布到 Web 根目录。

## 3. API 独立发布

### 3.1 环境变量

在 API 服务器创建 `/opt/growth-dashboard/app.env`，权限设为 600，由服务账号读取。示例：

```ini
PORT=7100
FRONTEND_ORIGINS=https://dashboard.example.com
COOKIE_SECURE=true
DB_URL=jdbc:mysql://<数据库主机>:3306/dashboard?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
DB_DRIVER=com.mysql.cj.jdbc.Driver
DB_USER=<数据库账号>
DB_PASSWORD=<数据库密码>
AI_BASE_URL=
AI_API_KEY=
AI_MODEL=
```

多个允许的前端 Origin 用逗号分隔，只允许实际 HTTPS 来源，不使用 `*`。`COOKIE_SECURE=true` 与 HTTPS 必须同时启用。AI 配置保持空白即不启用远程 AI；不要提交真实凭据。

使用默认 H2 时省略 MySQL 五项配置，数据库位于服务运行目录 `data/dashboarddb.mv.db`。生产升级前必须备份；H2 建议停止服务后复制整个 `data` 目录，MySQL 使用 `mysqldump` 并验证备份可恢复。

### 3.2 systemd 与 Nginx

1. 将 Jar 上传到 `/opt/growth-dashboard/releases/<后端版本>.jar`，更新 systemd unit 指向的版本，或用受控软链接切换。
2. 将 `deploy/growth-dashboard.service` 安装到 systemd，使用低权限 `dashboard` 账号运行。
3. 将 `deploy/api-nginx.conf` 中示例域名和证书路径替换为占位部署值，安装到 API Nginx。
4. 执行 `nginx -t` 后重载 Nginx，再启动或重启 `growth-dashboard`。
5. 确认云安全组和主机防火墙均未公开 7100。

## 4. 前端独立发布

1. 在前端服务器将本次 `dist` 解压到 `/srv/growth-dashboard/frontend/releases/<前端版本>/`。
2. 将 `/srv/growth-dashboard/frontend/current` 软链接原子切换到该版本目录。
3. 将 `deploy/frontend-nginx.conf` 中前端域名、API 域名和证书路径替换为实际占位值，执行 `nginx -t` 后重载。
4. 前端发布不需要重启后端，后端发布也不需要重新构建前端。

Nginx 行为：`index.html` 使用 `Cache-Control: no-cache`，带内容哈希的 `/assets/` 缓存一年且 immutable；未知前端 history 路由回退到 `index.html`；`/api` 与 `/api/**` 绝不回退到 HTML。两个站点均设置 nosniff、DENY、Referrer-Policy 和 HSTS，前端启用 gzip。

## 5. 回滚与数据库

前端和后端分别保留上一个可用版本：

- **前端回滚**：将 `current` 软链接切回上一个前端版本并 reload Nginx；`index.html` no-cache 使客户端重新发现旧资产。
- **后端回滚**：先备份数据库，将 systemd 的 Jar 版本切回上一个后端版本，重启服务并执行健康检查。若新版本已做不兼容数据库变更，必须先恢复兼容备份；不要在未验证恢复流程时直接回滚。
- 两端版本可独立回滚，但涉及 API 契约变更时必须按兼容顺序发布，并同时核对前端 API client 版本。

## 6. 健康检查与部署冒烟

以下检查应在两个站点各自及组合链路上执行：

```bash
# 存活：未登录返回 401 JSON 即表示 API 正常，不应超时或返回 HTML。
curl -i https://api.example.com/api/auth/me

# SPA history：应返回 index.html。
curl -i https://dashboard.example.com/tasks

# API 不 fallback：应返回 404 JSON，不得包含 <!doctype html>。
curl -i https://dashboard.example.com/api/not-a-resource

# 缓存与压缩：index no-cache，assets immutable；以 Accept-Encoding: gzip 验证压缩。
curl -I https://dashboard.example.com/index.html
curl -I -H 'Accept-Encoding: gzip' https://dashboard.example.com/assets/<构建资产文件名>

# CORS：仅配置的前端 Origin 可通过预检，凭证允许但不得为通配符。
curl -i -X OPTIONS https://api.example.com/api/tasks \
  -H 'Origin: https://dashboard.example.com' \
  -H 'Access-Control-Request-Method: POST' \
  -H 'Access-Control-Request-Headers: Content-Type,X-CSRF-TOKEN'
```

浏览器登录后检查 `DASHBOARD_SESSION` 具有 `HttpOnly; Secure; SameSite=Lax; Path=/`。读取 `/api/auth/csrf` 后，所有 Cookie 会话写请求必须携带 `X-CSRF-TOKEN`；缺失或错误令牌应返回 403，退出登录仍须通过 CSRF。不得用 Nginx 添加宽松 CORS 规则覆盖后端白名单。

## 7. 自动化与手动验收

```bash
# 根目录
mvn clean test && mvn package
node --test deploy/deployment-contract.test.mjs
node deploy/smoke-test.mjs   # 真实 Jar、生产 Cookie/CSRF/CORS；JAVA_CMD 可指定 Java 17

# 前端；Playwright 自动启动并清理隔离内存数据库后端与 Vite
cd frontend
npm ci && npm run lint && npm test && npm run build && npm run test:e2e
```

Windows 默认使用 Edge；其他平台需安装 Playwright Chromium。E2E 使用独立临时实例，不接触真实 `data/dashboarddb.mv.db`。

发布前手动核对：

- [ ] 390、768、1440 三种宽度下导航、任务、搜索和表单可用，无横向溢出。
- [ ] 深浅主题均清晰；加载、错误、空状态可识别且可恢复。
- [ ] 登录、创建、编辑、完成、排序、刷新顺序保持、全局搜索和退出正常。
- [ ] 管理员可访问账号、复盘、人才；level 3 直接输入受限 URL 会返回工作台。
- [ ] 刷新 `/tasks` 等 history 路由不 404，未知 API 始终返回 JSON 错误而非 index。
- [ ] Cookie、CSRF、CORS、安全 Header、gzip 和静态缓存符合第 6 节。
- [ ] 能力成长/评估前端入口保持隐藏，后端既有接口未删除。
- [ ] 演示账号已改密或删除，环境文件权限正确，备份和回滚均已演练。
